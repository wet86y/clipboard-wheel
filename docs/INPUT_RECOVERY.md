# 输入复位与按键释放

## 用户行为

在当前 Windows 桌面按物理 Esc（取消键）、左 Win 或右 Win（Windows 键），都会暂停中键捕获，并作废当前轮盘及尚未执行的动作。轮盘没有显示时也有效。Esc/Win 原有系统行为保留，因此按 Win+V 等系统组合键也会暂停捕获。

暂停会同步到托盘和现有配置。只有用户明确重新启用中键捕获才恢复；锁屏解锁、休眠恢复、钩子重装、心跳恢复和保存旧设置草稿都不清除暂停。剪贴板历史监听继续运行。

Esc/Win 不参与设置页的快捷键录制。程序合成的这些按键不会触发急停，已有包含 Win 的轮盘组合键仍可发送。

## 实现约束

- `KeyboardInput`（键盘输入安全服务）统一处理快速复制、粘贴和扩展组合键。注入前已经按下的键不会由该动作再次按下或释放。
- 本程序按下但没有可靠松开的键保留在释放账本中。松开发送立即重试最多三次；仍失败时由独立输入线程的 50 毫秒看门狗继续重试。即使发送器报告成功，系统仍显示按下时也保留恢复任务。
- 手动复位还会尝试清理账本以外遗留的左右 Ctrl/Shift/Alt/Win（控制键/上档键/交替键/Windows 键）逻辑状态。物理按键状态由低级键盘事件单独维护，补偿不会主动松开用户仍按住的键。
- 钩子回调只更新原子状态并投递通知，不获取发送互斥锁、不调用 `SendInput`（模拟输入）。释放重试在回调返回后执行，避免输入钩子与发送线程互相等待。
- 急停锁存在输入线程立即生效，不等待主界面。界面恢复处理消息时，再隐藏轮盘、停止录制、取消待粘贴和排队动作、刷新托盘及保存暂停状态。
- 输入代次的最低位表示暂停，每次复位/重新启用均向前推进。轮盘、扩展动作和两阶段粘贴携带创建时的代次，重新启用后旧操作也无法复活。
- 按键按下和外部窗口/程序操作必须在副作用前取得与急停共享原子字的提交许可。急停之后不能取得新许可；急停前已经取得许可的在途操作仍可能完成，其模拟按键会继续执行配对释放，外部程序操作不能回滚。
- 鼠标急停保留此前被拦截按下的迟到松开配对；此后新的点击正常透传。
- 独立输入线程还轮询 Esc/Win，作为钩子安装失败、回调延迟或被系统静默移除时的备用检测。已知合成按键不参与该检测。
- 快捷键录制钩子安装后，会请求独立输入线程重新安装安全键盘钩子，将安全观察点移到钩子链首部；录制器本身也放行复位键并通知同一暂停状态。

普通进程无法越过 Windows 安全桌面和输入权限限制。复位只能在本进程能够观察到输入的桌面生效；被权限限制阻止的按键释放会保留并重试。已提交给外部应用的操作无法撤销。

## 托盘恢复

托盘使用隐藏顶层窗口接收 `TaskbarCreated`（任务栏重建通知），重新注册图标并设置通知版本。每两秒检查一次注册状态；修改失败后尝试重新添加。首次自启时任务栏尚未就绪，不结束进程，而是继续重试。恢复图标沿用当前启用/暂停状态。

## 诊断字段

诊断配置保留以下记录；正式发布配置沿用现有规则，不编译这些日志。

| 事件/字段 | 中文说明 |
|---|---|
| `input.keyboard.chord` | 统一组合键发送完成记录 |
| `generation` | 操作使用的输入代次 |
| `requested_keys` | 请求发送的键数量 |
| `pressed_keys` | 本次实际成功按下、需要配对释放的键数量 |
| `pending_releases` | 仍保留在账本中的待释放键数量 |
| `success` | 本次发送及即时释放尝试是否成功，且代次仍有效 |
| `input.quick_copy` | 快速复制发送结果 |
| `input.emergency_pause` | 界面已同步暂停和取消操作 |
| `tray.icon.registered` | 图标注册或恢复成功 |
| `version_set` | 通知版本是否设置成功 |
| `tray.icon.retry` | 托盘暂不可用，等待重试 |
| `retry_ms` | 托盘重试间隔，单位为毫秒 |

## 验证

`native_input_safety`（输入安全测试）使用假的键盘发送器、按键状态查询器和托盘服务模拟故障，不向真实桌面注入按键，也不重启资源管理器。覆盖每一个按下位置失败/急停、松开重试、逻辑残留、物理键保护、录制器放行、鼠标配对、旧代次失效以及托盘首次注册和重建恢复。

完整验证仍使用 `scripts/run-self-check.ps1`，人工场景见 `docs/ACCEPTANCE_TESTS.md`。
